# QiCore — Make Physical Products by Simply Describing What You Want

> QiCore 让创造，自然发生。

这是 QiCore 官网的源代码。它同时也是一份关于 QiCore 的小型工作日志：我们在这里介绍公司、记录产品、表达设计判断，也把“如何让一个想法走向真实世界”变成可以被浏览、触摸和继续搭建的界面。

```text
idea  →  prototype  →  reality
```

## QiCore 在做什么

QiCore 是一家面向下一代智能硬件的产品与技术公司。我们把设计、软硬件工程、验证和制造放在同一条创造路径上，关注的是完整的产品，而不是孤立的技术环节。

我们相信，数字世界已经越来越容易被创造，而物理世界仍然被专业工具、学科边界和复杂流程分割。QiCore 想做的是缩短这段距离：让人可以从自己的意图出发，经过清晰的设计与工程协作，最终得到一个真实、可工作的产品。

### OysCat：第一步

OysCat 是 QiCore 的第一款产品，也是这套创造方式的第一个入口。它由两层组成：

- **Electronic Modules**：将运动、灯光、传感、声音与控制等物理能力封装成可复用的标准化硬件模块。
- **Workspace**：把建模、编程、仿真和硬件控制放进同一个 AI 驱动的工作空间。

OysCat 不只是一个黑色的电子模块，也不只是一个软件界面。它更像一组可以不断组合的词汇：用户描述想要什么，系统帮助把意图翻译成结构、逻辑和动作，再把它带回现实。

## 官网不是一张海报，而是一张工作台

QiCore 官网的视觉核心不是“大字报”，而是一个持续存在的创作画板。首页的积木、纸张、网格和标记，共同构成一个可以进入不同信息层的工作台。

### 1. 纸张：让信息有呼吸

页面以暖白纸张、细线边框和低对比网格为基础。卡片不是漂浮在纯色背景上的孤岛，而像被放在同一张桌面上的不同研究页：它们之间有边界，但仍然共享同一个空间。

### 2. 积木：让抽象概念可以被看见

首页的积木不是装饰物。它代表 QiCore 的工作方式：把复杂的系统拆成可以理解、连接和重新组合的单元。设计、代码、制造、产品和团队信息，都以不同形态成为画板上的一块积木。

### 3. 轻微透视：保留手感，不牺牲阅读

首页允许画板随指针产生轻微的空间变化；内容页则大幅降低运动幅度，让信息仍然稳定、易读。交互的目标不是炫技，而是让用户感到自己正在一张真实的工作台前移动。

### 4. 纸页转场：信息从同一张画板长出来

从首页进入 About、News 或 Team 时，导航栏会先升起，新的内容从它下面逐层展开；返回首页时，内容收回，画板重新成为主角。转场使用克制的加减速，而不是突兀的跳转，保持“同一空间中的换页感”。

### 5. 两种视觉角色：QiCore 与 OysCat

- **QiCore** 是公司与创造系统：亮色、纸张、网格、克制的排版，强调长期主义、协作和完整产品路径。
- **OysCat** 是产品入口：保留 QiCore 的纸张与留白，但允许黑色电子模块、绿色信号和更明确的产品语言出现。

两者不是两套互不相干的品牌，而是同一条路径上的两个层级：QiCore 讲“为什么以及如何创造”，OysCat 展示“第一件被创造出来的东西”。

## 技术结构

- **Next.js 15 + React 19**：页面与组件化内容结构。
- **TypeScript**：约束页面、交互和视觉组件的边界。
- **Three.js / React Three Fiber**：用于首页积木画板和部分空间化视觉。
- **CSS-first visual system**：纸张、网格、卡片、转场和响应式布局主要由 CSS 驱动。
- **Static Export**：生产环境输出静态页面，适合部署到 Vercel，降低运行时依赖。
- **In-page bilingual content**：中英文内容共存，通过 `data-lang` 切换，避免语言切换时先闪过另一种语言。

核心目录：

```text
app/                    # 页面路由与页面级内容
components/             # 导航、画板、产品转场、影片等共享组件
hooks/                  # 性能等级与交互相关 hooks
lib/                    # 站点数据和 QiCore 路由状态
public/brand/           # QiCore / OysCat 品牌资产
public/media/           # 产品与新闻媒体
public/illustrations/   # QiCore 内容页插图与概念资产（仅本地，不入库，见 .gitignore）
tests/e2e/              # 页面和路由回归测试
tests/perf/             # 运行时与交互性能基准
ops/recruitment-mailer/ # 私有部署的投递确认邮件 Worker（仓库中不含任何生产凭证）
```

招聘岗位的飞书内容同步、投递自动化和确认邮件链路记录在
[`ops/recruitment-mailer/README.md`](ops/recruitment-mailer/README.md)。公开仓库只保存代码、数据契约和脱敏配置模板；所有凭证、资源 ID、内网信息和候选人数据必须留在部署环境。

## 本地开发

```bash
npm install
npm run dev
```

默认开发地址为 `http://localhost:3000`。如果 3000 端口被占用，可以指定端口：

```bash
npm run dev -- --port 3012
```

常用检查命令：

```bash
# 类型检查
npx tsc --noEmit

# 生产构建与静态导出
npm run build

# E2E 页面回归
npm run test:e2e

# 构建后运行 E2E
npm run test:e2e:ci

# 运行时性能基准
npm run test:perf
```

## 部署说明

项目使用 Next.js 静态导出：

```js
// next.config.mjs
output: "export"
```

构建结果位于 `out/`，Vercel 配置位于 `vercel.json`。其中 `/about`、`/news`、`/team`、`/oyscat` 等路径会重写到对应的静态 HTML，确保直接访问内容页时不会被当成 TXT，也不会因为静态路由缺失而出现 404。

部署前至少执行：

```bash
npm run build
git diff --check
```

## 设计与开发约定

1. **先保证层级，再添加效果。** 插图、色块和动画都服务于信息，不让装饰抢走内容。
2. **保持 QiCore 的克制。** 低对比网格、细边框和少量颜色比大面积渐变更接近品牌的长期气质。
3. **OysCat 可以更黑，但不能脱离画板。** 黑色模块是产品特征，纸张、留白和排版仍然继承 QiCore。
4. **动作要有物理感，幅度要小。** 进入、退出、悬浮和透视都需要加减速；阅读内容页时优先稳定与可点击性。
5. **所有视觉变化都要考虑性能。** 低性能设备应能减少透视、粒子和高成本动画，而不影响页面信息结构。
6. **不要破坏真实资产。** OysCat 商标、猫头、产品模块图和视频入口应优先使用已有品牌资产，生成图只作为经过设计审核的补充。
